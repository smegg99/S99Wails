# S99Wails

`s99wails` is a set of reusable building blocks for Wails v3 desktop apps:
OS accent and dark-mode detection, native-side localization, a theme-aware
system tray, window-state persistence, autostart, environment workarounds,
and ready-made Wails services.

[USAGE.md](USAGE.md) is how an app imports it.

## Why

Every Wails app I built started by copying the previous app's desktop
shell: the tray manager, the accent watcher, the webkit workarounds (gtk 4 works very badly under amd on wayland, at least in my case, using gtk 3 fixed it), the
locale wrapper. The copies drifted apart. This module is that shared part,
extracted once, so the next app imports it instead. Pairs well with
[s99config](https://github.com/smegg99/S99Config) and
[s99logger](https://github.com/smegg99/S99Logger).

## Features

- `platform/accent`: OS accent color and dark/light scheme, with a change watcher.
  Linux (XDG portal), Windows (registry), macOS (defaults). No Wails
  dependency.
- `platform/notify`: lazy Linux notification transport shared by native callers;
  failures remain errors, and the next send reconnects. Other platforms return
  `errors.ErrUnsupported`.
- `platform/autostart`: launch on login, per user, no elevation. XDG `.desktop`,
  registry Run key, LaunchAgent.
- `platform/env`: WebKitGTK DMABUF workaround, AppImage detection, opt-in X11
  default for Plasma Wayland sessions.
- `locale`: go-i18n wrapper for native-side strings with plurals, template
  data, language matching, and an OnChange hook. No Wails dependency. It loads
  the flat JSON `backend` target of [S99Locale](https://github.com/smegg99/S99Locale)
  (`loc build`), which also emits the vue-i18n frontend catalogue from the same
  source; `loc check` keeps the two in step.
- `shell/tray`: theme-aware tray icon with serialized updates, re-localizable
  menus, click-to-toggle, and close-to-tray. On Linux it is its own
  StatusNotifierItem over D-Bus, so the panel draws the SVG icon theme;
  Windows and macOS use the Wails tray.
- `shell/window`: resize limits written onto `application.WebviewWindowOptions` in
  one call. They bind on X11 and on Wayland.
- `shell/windows`: account-scoped native workspaces, acknowledged tab transfers,
  close/quit barriers, geometry clamping and cross-window tab drag (X11 pointer, Wayland drag and drop).
  The app supplies persistence and view payloads. See [USAGE](USAGE.md#native-workspaces).
- `shell/editkeys` and `shell/mousenav`: edit shortcuts and mouse navigation
  events addressed to the window that received the input. `editkeys.Watch`
  also keeps WebKitGTK 2.54 from crashing on a paste from a selection nothing
  owns (X11).
- `shell/crash`: a watcher copy of the program that opens the app's own
  frontend as an error screen when the app cannot start, crashes, stops
  responding or is killed. See [USAGE](USAGE.md#error-screen).
- `shell/windowstate`: window geometry persisted across runs behind a two-method
  Store interface.
- `services/{browser,logger,theme,title}`: Wails-bound services with typed TS
  bindings generated by `wails3 generate bindings`.
- `proxy`: mounts a daemon's HTTP API into the webview at same-origin `/api`
  over a unix socket (no port, no CORS) and flushes Server-Sent Events as they
  arrive.
- `traygen`: pregenerates tray icons per theme and state from labeled SVGs
  plus a CUE config, with typed Go accessors, and optionally the app's own
  icon as an embedded PNG.
- `frontendgen`: emits the Vue composables (runtime detection, locale
  sync, system theme, log bridge, window title, edit keys, crash screen) into your app's frontend
  tree, no npm packaging.
- [`webbench`](./webbench): measures a page inside WebKitGTK and compares
  render-path configurations, one child process per configuration.
  `cmd/s99webbench` is the command that drives it. Linux only.

## Prerequisites

Everything under `platform/`, plus `locale`, builds with the Go toolchain
alone and cross-compiles cleanly. `shell/` and `services/` touch a window, so
they need the platform's webview stack:

- Go 1.27+
- CGO enabled and a C compiler (gcc or clang), for any Wails build and for
  `webbench`
- GTK 3 dev headers: `libgtk-3-dev` on Debian, `gtk3-devel` on Fedora
- WebKit2GTK 4.1 dev headers: `libwebkit2gtk-4.1-dev`,
  `webkit2gtk4.1-devel`
- Node.js and pnpm, only to run the TypeScript half of `just check`

`webbench` and `cmd/s99webbench` are Linux only: `webbench.Run` lives in a
cgo file behind a linux build tag, so the command does not compile elsewhere.

## Install

This repository is private, so `go get` needs Go pointed away from the public
proxy and git pointed at ssh:

```sh
go env -w GOPRIVATE='github.com/smegg99/*'
git config --global url."ssh://git@github.com/smegg99/".insteadOf "https://github.com/smegg99/"
```

Set both. `GOPRIVATE` alone makes Go fetch over direct git, which then has no
credentials. proxy.golang.org still serves v1.0.0 through v1.0.4 without any
configuration; v1.1.0 and later are not on the public proxy.

```sh
go get github.com/smegg99/s99wails/v2
go get -tool github.com/smegg99/s99wails/traygen/v2
go get -tool github.com/smegg99/s99wails/v2/frontendgen
```

In v2 the OS-facing packages live under `platform/`, the window and tray ones
under `shell/`, and the import path carries the `/v2` suffix. `traygen` is a
separate module; the code it emits imports `shell/tray`, so it also carries the
suffix and is tagged `traygen/v2.0.0`.

The module pins upstream `wails/v3 v3.0.0`. On Linux, build with
`-tags gtk3` (WebKit2GTK 4.1); the GTK 4 stack renders a blank window on many
GPU setups.

After v1.0.4 this module also requires
[s99ab](https://github.com/smegg99/S99AB), which is private too. It is pinned
to a released tag, not a `replace`, because a dependency's `replace` does not
apply to your build. The ssh configuration above lets your build fetch it.

To develop against local checkouts instead of released tags, point replace
directives at them in your app:

```
replace (
	github.com/smegg99/s99wails/v2 => ../S99Wails
	github.com/smegg99/s99wails/traygen/v2 => ../S99Wails/traygen
	github.com/smegg99/s99ab => ../S99AB
)
```

## Quick Start

A localized tray with theme-aware icons, wired for locale changes:

```go
locales, _ := locale.New(localeDir, "en")

manager := tray.NewManager(app, tray.Options{
    Icons:   trayicons.ForStatus(trayicons.StatusIdle), // traygen output, or your own IconsFunc
    TemplateIcon: trayicons.TemplateIcon,
    Tooltip: func() string { return locales.T("tray.tooltip") },
    OnClick: func() { tray.Toggle(window) },
})
manager.RegisterEvents(app)
defer manager.Close()

manager.SetMenu(func() []tray.Item {
    return []tray.Item{{Label: locales.T("tray.show"), OnClick: func() { tray.Show(window) }}}
})
locales.OnChange(manager.RebuildMenu)

tray.CloseToTray(window, func() bool { return cfg.CloseToTray }, quitting.Load)
```

`examples/minimal` is the full wiring. The config package (CUE schema and
generated types), `main.go`, and your menu builder stay in the app;
`examples/configservice` is the starting point for the config part.

## Code generation

Both generators run through `go generate ./...` next to your other
generated code, and `wails3 generate bindings` emits typed TS models for
the services (including `accent.Info`).

traygen: declare states in `trayicons.cue`, label recolorable elements in
your SVGs with `inkscape:label`, and one icon per theme and state comes
out, plus typed accessors. Rendering is resvg in wasm: no system
dependencies, deterministic output.

Linux publishes SVGs by native icon-theme name, with PNG pixmaps available
for hosts that cannot resolve SVGs. Windows gets a multi-resolution ICO;
macOS gets a menu-bar PNG with a Retina-sized primary and optional template
tinting. Artwork stays centered, keeps its aspect ratio and receives a
platform-specific transparent inset. See [USAGE.md](USAGE.md#tray-artwork)
for sizes, separate hand-editable sources and native-size preview sheets.

```cue
prefix: "app-tray"
slots: ["badge"]
themes: {
    dark:  source: "logo-dark.svg"
    light: source: "logo-light.svg"
}
states: {
    idle: {}                          // slots without a color are hidden
    error: slots: badge: "#FF0000"
}
```

```go
// next to the SVGs and trayicons.cue:
//go:generate go tool traygen -config trayicons.cue

// switch states at runtime:
manager.SetIcons(trayicons.ForStatus(trayicons.StatusError))
```

An optional `appIcon` block renders one more SVG as is, with no themes and
no states, for the window and the taskbar. The first size is embedded as
`AppIcon`; the others are written beside it as `<prefix>-app-<N>px.png`.
Wails on Linux takes PNG bytes here, not SVG. `appicon/` under `-out` is
generated and removed on every run, so keep the source elsewhere; traygen
refuses a source inside it.

```cue
appIcon: {
    source: "app-icon.svg" // relative to trayicons.cue
    sizes: [256]           // the default
}
```

```go
application.New(application.Options{Icon: trayicons.AppIcon})
```

frontendgen: the Vue composables ship the same way. The emitted files
import only `vue` and `@wailsio/runtime`; binding services are injected by
the caller.

```go
//go:generate go tool frontendgen -out ../frontend/app/composables/s99wails
```

## Development

`just check` runs `gofmt`, `go vet` and `go test` across all three modules
(root, `traygen`, `examples`), eslint and tsc over the TypeScript assets, the
VERSION drift check, and two regeneration diffs: `examples/frontendgen/gen`
against `frontendgen/assets`, and `examples/traygen` against its SVGs and CUE.

```sh
just            # list recipes
just check      # everything
just fix        # eslint --fix
just frontendgen  # regenerate the emitted composables
just traygen      # regenerate the example tray icons
```

`VERSION` is the source of truth for the version; `just set-version 2.0.1`
writes it and `package.json` together. `package.json` exists only for eslint
and tsc; the composables reach an app through frontendgen, not npm.
